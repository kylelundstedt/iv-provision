## Result

**PASS — bounded remember / wait / wake / act / record test, without Rex.**
Observed on `iv-cmg-concierge` on **2026-10-14**. The Manager created one
nonrecurring task, the initiating CLI disconnected, the host later woke a
separate task session, and that session recovered saved state and recorded
completion. A subsequent read-only conversation recovered the result.

This demonstrates the core resident mechanism, **not** complete qualification
of the [Resident Layer](resident-layer.md) or the
[Rex project-management workflow](rex-based-project-management.md).

## Procedure

1. Ask the Manager to create one experiment JSON file containing a synthetic
   marker, `phase=waiting`, and `completion_count=0`.
2. Ask it to create exactly one nonrecurring task about three minutes ahead,
   acknowledge the task ID, and end the turn. No retries or additional work.
3. The follow-up prompt references the file but does **not** contain the marker.
   It instructs the scheduled session to read the saved marker, set
   `phase=awaiting_owner` and `completion_count=1`, and send one completion
   message to the existing `local-cli` destination.
4. Allow the initiating CLI and SSH connection to exit. Do not invoke the task
   manually or send a second message to wake it.
5. After the deadline, inspect the state file, task run metadata, mailbox
   records, processing acknowledgments, and host wake log.
6. Reconnect once to the original Manager conversation with a read-only question
   about the saved result. Do not rerun the experiment.

## Limits and next qualification

Not tested: worker completion as a wake source, multi-agent handoffs, independent
review, enforced approval boundaries, service/VM restart recovery, replay or
duplicate-delivery recovery, model/provider handover, subscription exhaustion,
notification delivery while absent, or any Rex integration. A count of one in
this run is not proof of exactly-once behavior under failure.

No inference-cost or idle-resource measurements were collected. This test does
not requalify the existing Echo/runner compatibility caveat or gateway isolation.

The next small experiment should test an existing specialist's reply waking the
Manager and producing a durable pending decision, still using synthetic content.
Recovery testing should be a separate approved interruption, not an incidental
restart of the concierge service.
